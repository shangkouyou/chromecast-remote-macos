# v1.1.0 — 按需虚拟管道（对齐“无线麦”设计）

## 变化

- 音频桥从“常驻虚拟设备”改为**按需虚拟管道**：按住语音键（ATVV `0x04`）时才创建到
  `Google TV 2ch` 的独立输出，松开（`0x00`）立即关闭。
- 因此切换系统输出（蓝牙耳机、外接显示器、扬声器、默认输出设备）**不会**影响语音管道。
- 每次按下时重新按名字解析虚拟设备，即使中途 `coreaudiod` 重启，下一次按下也会用新设备。
- 每次按下时才把系统输入切回 `Google TV 2ch`，不持续抢占；开视频会议时可手动切回
  Mac 麦克风，不会被改回去。
- 启动时不再初始化音频引擎，消除启动卡死；保留单实例锁、日志源自动重启、心跳看门狗。
- 音频初始化顺序调整：先设置输出设备，再连接播放器，减少 `AudioUnitSetProperty` 卡住。
- 安装脚本把 CLI 复制到 `~/Library/Application Support/gvtv-remote/` 并从那里运行，
  避免 Documents/iCloud 路径导致的启动卡顿。

## 验证

- 输出 `L32p-30` → 按住语音键，文字与系统声音正常；
- 输出切到 `MacBook Pro 扬声器` → 语音正常；
- 输出切回 `L32p-30` → 语音正常；
- 录音端检测到非零波形，输入法正常上屏。

## 升级

```bash
python3 tools/remote-mic/build.sh
./scripts/install-mic.sh
```

设置保持不变：

| 位置 | 选择 |
| --- | --- |
| 系统输出 | 真实设备（蓝牙耳机 / 扬声器 / 显示器） |
| 系统输入 | `Google TV 2ch`（或 BlackHole 2ch） |
| 输入法麦克风 | `Google TV 2ch`（或 BlackHole 2ch） |

## 已知边界

- 在**按住语音键说话的过程中**切换输出，当前这一句可能被打断；松开再按一次即可。
- 正常“先切输出、再按语音”完全不受影响。
